## 0. 先算账：费率结构决定了什么

| 路径 | 净手续费 | 含义 |
|---|---:|---|
| maker 开 + maker 平 | **+1.0 bp**（收） | 理想路径，不赚价差也有 1 bp |
| maker 开 + taker 平 | **−1.0 bp**（付） | 每次被迫吃单平仓，相对理想路径差 2 bp |
| taker 开 + taker 平 | −3.0 bp | 基本不该出现 |

每笔 maker 成交的期望收益：

```
edge = 半个价差（成交价相对公允价）+ 0.5 bp 返佣 − 逆向选择（成交后 markout）− 库存处理成本摊销
```

推论：

1. **返佣只有 0.5 bp，逆向选择通常远大于它**。BTC/ETH 这类一档价差的品种，赚钱几乎全靠"不被毒单打到"和排队位置，而不是价差。
2. **taker 平仓贵**（1.5 bp + 半个价差），所以库存要靠报价倾斜（skew）用 maker 慢慢消化，吃单只作为风控兜底。**去库存的优先级（用户确认 2026-11-05）**：Bitget 报价倾斜 maker 消化 → 必须对冲时用 **Binance maker** 对冲 → Bitget taker 兜底。Binance taker 没有费率优势，不用。
3. **保本条件**：在某个持有期 h 上，平均 markout（不利方向为负）> −(半价差 + 0.5 bp)。这是所有因子最终要服务的 y。
4. 返佣**没有门槛**（用户确认 2026-11-05：无成交量占比、在线时长、价差/深度义务）。tick、频率限制见第 3.1 节。

## 1. 预测目标（y），先定好再谈因子

| y | 定义 | 用途 |
|---|---|---|
| 短期中间价收益 | `ln(mid[t+h]/mid[t])`，h = 100ms / 500ms / 1s / 5s / 30s | 公允价偏移、报价倾斜 |
| 成交 markout | 每笔自己的 maker 成交，相对成交后 h 时刻 mid 的盈亏（bp，按方向带符号） | **核心评估指标** |
| 成交概率 | 某档位、某排队位置的挂单在 Δt 内成交的概率 | 定报价距离 |
| 已实现波动 | 未来 h 内的 |收益| 或方差 | 定价差宽度、风控 |
| 毒性标签 | 成交后 h 内价格朝不利方向走超过 k bp | 分类器目标 |

## 2. 因子分类

### A. 公允价 / 微价格（决定报价中心）

| 因子 | 定义要点 | 备注 |
|---|---|---|
| mid | (bid1+ask1)/2 | 基准 |
| microprice | L1 量加权：`(bid·Qa + ask·Qb)/(Qa+Qb)` | 一档价差品种最有用 |
| 多档加权 mid / VAMP | 前 N 档或固定名义金额的量加权价格 | 抗 L1 闪烁 |
| 跨所复合公允价 | Binance/OKX/Bybit mid + 各自相对 Bitget 的基线偏移（A002 基线做法） | 见 D 类 |
| mark / index 偏离 | Bitget 标记价、指数价与 mid 的差 | 指数是多所现货，领先信息 |
| 最近成交价 vs mid | last − mid | 短期方向 |

### B. 订单簿状态（L1 + L2 50 档）

| 因子 | 定义要点 |
|---|---|
| 价差（tick 数 / bp） | 是否被 tick 卡住（spread = 1 tick 的占比） |
| L1 不平衡 | `(Qb−Qa)/(Qb+Qa)` |
| 多档不平衡 | 前 5/10/20 档，或按距离衰减加权 |
| 深度带 | mid ± 1/2/5/10 bp 内的买卖名义金额 |
| 簿斜率 / 凸性 | 累计深度对距离的回归斜率 |
| OFI（Cont 订单流不平衡） | L1 价位与量变化的带符号累积；多档 MLOFI |
| 新增 / 撤单速率 | 每档的 add/cancel 强度，撤单率 |
| 簿恢复力 | 被扫后回补到原深度的时间 |
| 排队消耗速度 | L1 量 / taker 成交速率 = 队列预计换手时间 |
| 大单闪烁 | 大挂单出现又撤（spoof 特征），存续时间分布 |
| 空档 | 前 N 档内的价位缺口 |

### C. 成交流（B125 `taker_imb` 的高频版本）

B125 里 53/125 个成员用到 `taker_imb`，是最重的主题；在做市时间尺度上对应如下：

| 因子 | 定义要点 |
|---|---|
| 主动买卖不平衡 | 100ms / 1s / 5s / 30s 窗口带符号成交量 / 总量 |
| 成交到达强度 | 笔数速率（B125 `count` 叶子的高频版）、Hawkes 自激强度 |
| 单笔规模分布 | 大单占比、规模分位数 |
| 扫单 | 一笔吃穿多档、trade-through 事件 |
| 同向连续成交 | run length |
| 价格冲击 / Kyle λ | mid 变化对带符号成交量的回归斜率 |
| VPIN | 等量桶内买卖不平衡，毒性代理 |
| 强平成交 | 强平事件流（Bitget 是否有公开流需确认；Binance/HTX 已采） |

### D. 跨所领先-滞后（对 Bitget 做市最可能有 alpha 的一类）

| 因子 | 定义要点 |
|---|---|
| 领先所收益 | Binance（及 OKX/Bybit）mid 在过去 Δt（50ms–1s）的收益 |
| 跨所偏离 | Bitget mid − 领先所 mid − 基线（A002 的时间加权基线） |
| 领先所成交流 | Binance 主动买卖不平衡、扫单事件 |
| 现货领先 | Binance 现货 BTCUSDT 对永续 |
| BTC 联动 | 做山寨时，BTC 的瞬时收益 × β（beacon 的 BTC 联动推算） |
| 行情时滞 | 交易所时间戳 vs 本地接收时间；自己的报价是否"过期"（stale quote） |

要点：Bitget 价格被其他所带着走时，挂在旧价位上的单就是被套利者吃掉的那一侧。**撤单 / 移价要比别人快**，所以这一类既是因子也是延迟问题。

### E. 波动率与状态（决定价差宽度和是否报价）

| 因子 | 定义要点 |
|---|---|
| 已实现波动 | 1s/10s/1m 收益平方和；高低价幅度（B125 `hl_range`） |
| 短长波动比 | 短窗/长窗，识别突变 |
| 跳跃检测 | 单步收益超过 k·σ |
| 活跃度 | 成交笔数、成交额（B125 `count`、`quote_volume`） |
| 日内季节性 | UTC 小时、资金费结算前后、美股开盘、宏观数据（CPI/FOMC）时点、周末 |
| 价差状态 | 当前价差相对其历史分布的分位 |

### F. 库存与持仓成本

| 因子 | 定义要点 |
|---|---|
| 库存 q | 名义金额、相对限额的比例 |
| 库存年龄 | 当前方向持有多久；平均回归半衰期 |
| 未实现盈亏 | 浮亏时是否加速去库存 |
| 资金费 | 当期 / 预测费率、距结算时间（B125 `funding`、`funding_prem`）；结算前倾向持有收费方向 |
| 去库存成本 | Bitget 吃单（1.5 bp + 半价差 + 冲击）vs 跨所对冲成本 |
| 保证金与强平距离 | 杠杆、可用保证金 |
| 多币相关库存 | 多币做市时用 BTC 等主币对冲净 β |

### G. 中低频偏置（B125 迁移过来，只做"倾斜"不做"报价"）

B125 是 1h–24h 的 CTA 因子，单因子 alpha 量级是每天几十 bp，放到做市里不能直接决定报价，但可以：

- 设定**目标库存 / 保留价倾斜**：趋势强时不在逆势方向积累库存；
- 决定**哪边报得更积极**。

可迁移的主题与叶子：

| B125 主题（成员数） | 叶子 | 做市里的用法 |
|---|---|---|
| 主动买卖流（53） | `taker_imb` | 1h 级别买卖压力 → 库存倾斜 |
| K线形态（44） | `clv`、`log_c_vwap`、`hl_range` | 价格相对 VWAP 的偏离 → 短期回归方向 |
| 资金费（41） | `funding`、`funding_prem` | 拥挤度、持仓成本 |
| 成交活跃度（30） | `count`、`volume`、`quote_volume` | 活跃度状态 |
| 多空比（21） | `ls_acct`、`ls_taker` | 拥挤度极值 → 踩踏风险 |
| 持仓量（14） | `oi` | OI 快速变化 + 价格方向 → 去杠杆风险 |

另外：beacon scout 的清算图推算（`/api/liqmap`）可作为"价格接近密集清算区时放宽价差 / 减库存"的风险因子。

### H. 事件与风险开关（不是 alpha，是"别报价"的条件）

- 强平潮、ADL、资金费触及上下限；
- mark 与 last 大幅背离、指数成分所断线；
- 交易所维护 / WS 断流 / 行情延迟升高；
- 上新、下架、合约参数调整；
- 新闻 / 公告冲击（暂无源）。

### J. 跨资产 / 宏观：纳指与 BTC

现状（2026-11-05 查过 beacon、basket-cta、qflow 各仓库）：**没有做成因子**。B125 全部是单币时序，不用任何外部资产；qflow collector 不采美股；唯一沾边的是 qflow 的 Gate TradFi CFD（只做了 XAU 执行）和 beacon scout 接了 Hyperliquid HIP-3（A009 的 `io:ANTH`）。

两个时间尺度，用法不同：

| 因子 | 定义要点 | 时间尺度 | 做市里的用法 |
|---|---|---|---|
| 滚动相关 `ρ(BTC, NQ)` | BTC 与纳指期货 NQ 的 5m / 1h 收益在 1d / 5d / 20d 窗口的相关系数（B125 `ts_corr` 同口径，任一序列恒定时缺失） | 慢 | 状态变量：相关高时 BTC 跟着美股走，美股时段和数据发布前后要放宽价差、降库存 |
| 滚动 β `β(BTC, NQ)` | `cov/var`（B125 `ts_reg_beta`） | 慢 | 把 NQ 的瞬时变化折算成 BTC 应有的变化 |
| NQ 瞬时收益 × β | NQ 过去 Δt（1s–1m）收益 × β | 快 | 公允价偏移，和 D 类跨所领先同一种用法：NQ 先动时撤掉 BTC 挂在旧价上的单 |
| 去纳指残差 | `BTC 收益 − β·NQ 收益`（B125 `ts_reg_resid`）的累积 | 中 | BTC 自身的偏离，看是否回归 |
| 纳指跳跃 | NQ 单步收益超过 k·σ，或成交量突增 | 快 | 风险开关（归 H 类）：先撤单 / 放宽，再按 β 重新定价 |
| 美股时段标记 | 现货开盘 9:30 ET、收盘 16:00 ET、CME 周日开盘、休市日、CPI / FOMC / 非农时点 | — | 日内季节性（归 E 类），相关和领先关系只在这些时段内成立 |
| 周末缺口 | CME 周日开盘价 − 周五收盘价，对比 BTC 周末已走的幅度 | 中 | 周一开盘时 BTC 是否要补涨 / 补跌 |

口径要点：

- **只在 NQ 交易时段有值**，休市时输出缺失（"不表态"），不能前向填充成 0 收益，否则相关和 β 都会被稀释。与 B125 稀疏算子"缺失 ≠ 0"同一规则。
- 时钟对齐：NQ 和 BTC 都用交易所时间戳对齐到同一网格，NQ 那一侧的时间戳要带上数据源延迟，不能用"未来可见"的价格。
- 先验：领先关系主要出现在美股开盘和宏观数据发布的几分钟内，平时很弱；相关性本身是随宏观环境漂移的，需要按窗口滚动而不是取全样本。

数据源（都还没接）：

| 源 | 优点 | 问题 |
|---|---|---|
| CME NQ 期货实时行情（Databento、IB 等） | 最权威，接近 23×5 交易 | 要付费；延迟行情做不了快因子 |
| QQQ / NDX 现货 | 数据好拿 | 只有美股常规时段 |
| 交易所里的纳指永续 / CFD（**Bitget `QQQUSDT` 已确认存在**，tick 0.145 bp、24h 约 25M USDT；另有 Hyperliquid HIP-3、Gate TradFi） | 7×24、走 WS、现有采集链路能接 | 美股休市时价格由币圈参与者自己定，不是外部领先信息，只能用美股时段的数据 |

## 3. 选币维度（做哪些合约）

| 指标 | 说明 |
|---|---|
| tick / 价格 | tick 大 → 价差被卡住、排队竞争激烈；tick 小 → 价差可变 |
| 平均价差（bp） | 半价差 + 0.5 bp 是每笔的毛 edge 上限 |
| 队列换手时间 | L1 量 / taker 速率，太长 = 排不到 |
| 成交额与 Bitget 份额 | 份额低的币更像跟随所，逆向选择更重 |
| 单位 tick 波动 | σ / tick，衡量价差相对波动是否够厚 |
| 竞争度 | L1 挂单笔数、改单频率 |

**初始宽松阈值**（按常识，上线后按 429 与回报延迟收紧或放开）：

- 单合约下单 + 撤单合计 ≤ 5 次/s（官方上限的一半），全账户 ≤ 8 次/s；
- 同一价位最短驻留 200 ms 才允许改价，避免盘口每跳一下就撤；
- 每合约同时挂单 ≤ 10（每边 ≤ 5 档）；
- 收到 429 后全账户退避 1 s 再恢复，连续 3 次 429 停止报价并告警。

| 合约参数（tick、挂单上限、资金费周期） | Bitget 公开 REST `/api/v2/mix/market/contracts` | 没有常驻采集，按需拉即可（第 3.1 节） |
| 山寨币 Bitget 盘口 | — | **没有**。按第 3.1 节候选（tick 0.5–2 bp）在 collector1 加 `bitget_futures_sbe` entry 即可，同一套代码；注意磁盘预算 |
| 纳指 | **Bitget 自己就有 `QQQUSDT` 永续**（24h 约 25M USDT），另有 NVDA、TSLA、MU 等美股合约 | 没采。最省事的 J 类采集点：collector1 加 `bitget_futures_sbe` QQQUSDT（L1 + trade）；美股时段才当外部信号用 |
| Binance maker 对冲腿 | qflow collector1 Binance BTC/ETH | 有行情；对冲执行与排队需另做 |
| 自己的成交 / 订单回报 | — | 没有，markout 和排队研究在上线小仓位后才有 |

结论：BTC/ETH 的 A–E 类可以直接用现有数据开始研究；但 BTC/ETH 在 Bitget 竞争最激烈，真正的价差空间更可能在中等流动性山寨，那需要先补采集。

## 5. 建议的研究顺序

1. 用 qflow Bitget BTC/ETH 数据算**被动成交模拟的 markout 分布**（假设挂在 L1，按成交穿越判定成交），看 0.5 bp 返佣够不够覆盖逆向选择。
2. 做 **D 类跨所领先-滞后**：Binance 领先 Bitget 多少毫秒、多大幅度，决定撤单/移价逻辑。
3. 对 A/B/C 类因子做 **对 1s/5s mid 收益的 IC**，筛出 microprice、OFI、多档不平衡里真正有用的。
4. 定库存模型（Avellaneda-Stoikov / GLFT 框架：保留价 = 公允价 + α − γ·q·σ²·T，半价差由 σ、成交强度、费率决定），把 F、G 类接进来。
5. 扩采集到候选山寨币，按第 3 节选币。
6. 纳指 J 类：先用 NQ 与 BTC 的 1m 历史 K 线算滚动相关 / β 和按美股时段分组的领先-滞后，确认"美股开盘与数据发布时 NQ 领先 BTC"是否成立、领先多少秒，再决定要不要接实时源。
