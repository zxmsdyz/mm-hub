# 挂单决策预测：成交条件 markout（设计 v0，2026-11-09）

> 回答用户 2026-11-09 的问题：「预测的是 30 s 后的 markout 吗？用什么模型？哪些因子？」
> 定位：这是**还没做过**的形态。此前 13 轮全是「先按规则挂、再用预测决定撤不撤」或「预测价格方向」（见 [bitget-mm-iteration-log.md](bitget-mm-iteration-log.md)、[bitget-mm-strategy.md](bitget-mm-strategy.md) §3 Tier 2、§11、§12）。本文把预测放到**挂单前**，预测对象是**「如果我在这里被成交，会亏多少」**，不是价格往哪走。
> 前提沿用已决事项（返佣 −0.5、API taker 1.5、UTA、BTC/ETH/SOL）。报价位置（touch / 偏离 k 档）是开放变量，不是既定前提。

---

## 0. 一句话

每次要挂单时，用**此刻可见**的信息预测两件事：这张单在 T 秒内会不会成交（p_fill），以及**如果成交，成交后 30 s 的 markout 是多少**（E[mo30 | fill]）；只在 `E[mo30 | fill] + 0.5 bp > 0` 时才挂。目标是把每笔净从现状的 BTC −0.36 / ETH −0.32 / SOL −0.19 拉到 0 以上，同时保住 ≥ 30% 的成交量。

---

## 1. 预测目标：为什么不是「30 s 后价格」

| | 价格方向预测（此前） | 成交条件 markout（本文） |
|---|---|---|
| 问题 | 未来 h 秒 mid 往哪走 | 我这张单**若被成交**，成交价对 30 s 后 mid 的差 |
| 样本 | 每个时间网格点 | 每次挂单决策；标签只在被成交的那部分有值 |
| 为什么不同 | 做市的亏损只发生在成交那一刻，而成交事件本身是筛选器：其他做市商撤空、价穿过我们时才轮到我 | 直接对准亏损发生的那个条件 |
| 已有证据 | R1/R2-b：方向 IC 0.45 但对成交毒性 AUC 0.49；R6-b 分钟级 ≈ 安慰剂 | E2-lite 事后分类 AUC 0.795（但增量来自活跃度）；Run A 实盘 2,200 笔成交有完整挂单时刻快照 |

**h 取 30 s 的理由**：Run A 里库存被对侧 maker 成交消化的典型时长在十秒到一分钟量级；30 s 也是 HTX 线和 Bitget 线一直用的口径，可与所有历史数字直接比。同时报 5 s 与 120 s，若 120 s 的符号与 30 s 不同，说明亏损在更长的持有期里才兑现，决策阈值要按库存半衰期对应的 h 取。

**标签**
- `y_mo`：成交后 30 s mid 相对成交价的 bp（不利为负），截断到 [−8, +8]。
- `y_tox`：`y_mo < −0.5`（亏过返佣）的二分类，作为稳健版。
- `y_fill`：挂出后 T=30 s 内是否成交（含部分成交）。

决策量：`net_post = p_fill × (E[mo30 | fill] + 0.5)`，门：`E[mo30 | fill] > −0.5 + m`，m 是安全边际（初值 0.1 bp）。

## 2. 因子（全部为挂单决策时刻可见，两所按交易所时间戳对齐，再叠加本地延迟）

按「Run A 已证明哪类信息真的在成交前可见」排序。

### G1 · Bitget 本地成交流（用户的四个 σ 口径，窗口 300 ms / 1 s / 5 s）
| 因子 | 定义 |
|---|---|
| `zB`, `zS` | ln(主动买量+ε)、ln(主动卖量+ε) 相对同长度窗口滚动参考分布的 z |
| `zK` | ln((B+ε)/(S+ε)) 的 z，只在 B+S ≥ 参考中位数时算数 |
| `zA` | ln((B+S)/n) 平均单笔规模的 z |
| 冲击侧量 | 对买单取卖方 zS、对卖单取买方 zB（σ 门实验用它单独做门无效，这里只作特征之一） |
| `rpi_share`（仅 SOL） | 最近 N 笔成交中 isRPI 占比（SBE trade 偏移 33）。**已知最强的一手信号**：SOL 被散户吃 +0.32 vs 被 API 吃 −0.76。BTC/ETH 恒 0，不可用 |

### G2 · Bitget 本档与盘口（这是 Run A 证明「成交前 10 ms 内」在变的东西，决策时刻只能看到它的慢分量）
| 因子 | 定义 |
|---|---|
| `qa`, `qa_rel` | 我若现在挂，前面的量；及其相对该档位近 1 h 中位的比 |
| `lvl_pull_100ms`, `lvl_pull_1s` | 本档量在最近 100 ms / 1 s 的净撤单比例（size 减少量 − 同期本价成交量）/ 期初量 |
| `l1_imb` | (bid1 − ask1)/(bid1 + ask1) |
| `depth_1bp`, `depth_5bp`（books50） | mid ± 1 / 5 bp 内自侧与对侧名义额、其比 |
| `spread_ticks` | 价差 tick 数（BTC/ETH 99% 为 1，SOL 偶尔 2） |
| `t_since_lvl_change` | 自侧最优价上次变动距今 |
| `frame_rate_1s` | 最近 1 s 的 L1 帧数（活跃度；books1 只在变化时推） |

### G3 · BN（在交易所钟下 BN 与 Bitget 同毫秒，这里 BN 只提供状态，不提供领先）
| 因子 | 定义 |
|---|---|
| `dt_bn_adverse` | 距最近一次 BN 自侧不利 tick 的毫秒数（Run A「state」基线，单独 AUC 0.71） |
| `bn_imb`, `bn_mp_dev` | BN L1 不平衡、微价 − mid（tick） |
| `bn_flow_1s`, `bn_flow_5s` | BN 带符号成交量 |
| `fv_lead_edge` | fv_lead − 我方拟挂价（tick） |

### G4 · 状态与时段
| 因子 | 定义 |
|---|---|
| `rv_10s`, `rv_60s`, `rv_300s` | 已实现波动 |
| `n_tr_5s` | 最近 5 s Bitget 成交笔数（E2 的 top 1，importance 0.10；它代表「会不会动」，要单独报去掉它之后的增量） |
| `utc_hour`, `is_weekend`, `min_to_funding` | 时段 |
| `side`, `q`, `batch_age`, `same_side_fill_streak` | 我方状态 |

### 不进特征的
BN 现货、跨所成交流（OKX/Bybit/Gate）、分钟级 CTA 因子、hazard：R3-s / R2-d / R6-b / R5-b 已证零增量。

## 3. 模型

| 层 | 选择 | 理由 |
|---|---|---|
| 主模型 | 梯度提升树（HistGradientBoosting / LightGBM），`y_mo` 回归 + `y_tox` 分类各一个，`y_fill` 分类一个 | 特征异质、非线性、样本 10^5~10^6 量级；E2-lite 已验证 HGB 在这类数据上可用 |
| 对照 | ① 只用 `dt_bn_adverse` 的单变量排序（Run A state 基线 AUC 0.71）；② logistic；③ **去掉活跃度族（`n_tr_5s`、`frame_rate`、`rv_*`）的 HGB** | ③ 是关键：若增量全来自活跃度，就是 R6-b / E2 的老结论——模型只学到「会不会动」 |
| 校准 | isotonic | 门槛是 bp 绝对值，需要校准的期望而不是排序 |
| 验证 | 按日 leave-one-day-out；IS 09-27~10-14 / HO 10-15~10-31 同号；**样本外 = Run A 实盘 2,200 笔成交**（BTC/ETH，挂单时刻快照 journal 已有） | 训练集来自修后引擎（已在复现日对上实盘 −0.845 vs −0.855）；实盘成交是最终裁判 |
| 评价 | 不看 AUC，看**经济量**：按预测值分十分位，各桶的 p_fill、E[mo30]、每笔净；选门槛后的「保留成交比例 × 每笔净 = 日净」，与 Tier 0 基线并列 | 门槛必须让 35 天库存链日净为正、净正日 ≥ 80% 才算过 |

**放行门**：IS/HO 同号；实盘 2,200 笔上按同一门筛出的子集每笔净 > 0；保留成交 ≥ 30%。三条都过才谈小额实盘。

## 4. 报价位置也是变量（用户 2026-11-08 纠正：挂 touch 从来不是拍板项）

同一套模型对 k ∈ {touch, touch 后 1 档, 2 档} 各预测一次 p_fill 与 E[mo30 | fill]（修后引擎的队列模型支持任意档位），挂在 `net_post` 最大的那一档；BTC/ETH tick 太小（0.013 / 0.04 bp）这条轴意义有限，**SOL（0.105 bp）上值得做**。

---

## 5. 预期与风险（先说清，免得又测一轮才发现）

- Run A 分析已证明：亏损主要发生在「其他做市商撤空后 1~4 ms 内被扫」，那一刻在挂单决策时刻**不可见**。模型最可能学到的是「活跃时少挂」，这会把量砍掉而每笔净未必转正——这正是对照 ③ 要揭示的。若去掉活跃度族后增量 < 0.05 bp，本线 DROP，不再调。
- 真正可能带来一手信息的只有 **SOL 的 RPI 占比**（对手方类型）。因此**SOL 应作为主战场**先跑，BTC/ETH 作对照。SOL 的 Bitget 采集 11-06 起才有，需要攒到 ≥ 14 天（11-20 后）才能训练；在此之前先用 Run A 的 BTC/ETH 实盘成交做可行性（本地、不开 box）。
- 打平需要的返佣：SOL 0.7 / ETH 0.8 / BTC 0.9 bp（现 0.5）。预测要补的缺口是 0.2 / 0.3 / 0.4 bp，SOL 最近。
