## 2. 状态机

```
IDLE ──触发(T)──▶ ARMED ──确认(c)──▶ LADDER(挂 3 层) ──任一层成交──▶ IN_POSITION ──出场──▶ IDLE / COOLDOWN
  ▲                  │ T_live 到期无确认 → IDLE                       │ 全部层未成交且 T_live 到期 → IDLE
  └── COOLDOWN(60 min，仅在止损类出场后) ──到期──▶ IDLE
```

### 2.1 触发 T（每个 Bitget L1 更新评估；两个方向对称，下以急跌-做多为例）

- `mid = (bid1 + ask1)/2`；`dd = (mid_t / max(mid over (t−10 s, t]) − 1) × 1e4`。
- 条件 1：`dd ≤ −10 bp`。
- 条件 2（流量门 F）：过去 10 s **卖方主动**成交名义额 ≥ 5 × 过去 1 h 内不重叠的 10 s 窗口名义额的中位数（360 个窗口；不足 1 h 数据时用已有窗口，少于 30 个窗口不触发）。
- 触发后该方向**解除武装**，直到 `dd` 回到 > −5 bp 才重新武装（防重复触发）。
- IN_POSITION 或 COOLDOWN 期间不接新触发。
- 急涨-做空：把 `dd` 换成 `du = (mid_t / min(mid over (t−10 s, t]) − 1) × 1e4 ≥ +10 bp`，流量门看买方主动成交。

### 2.2 确认 c 与挂梯子

- 触发后记录 `low` = 触发以来 mid 的最低值（实时更新）。
- 当 `mid ≥ low × (1 + 2/1e4)`（从低点反弹 2 bp）⇒ 确认，立刻挂梯子；触发后 180 s 内未确认 ⇒ 放弃，回 IDLE。
- 梯子：3 张 post_only 买单，各 1 层，价格 = `floor_tick(min(bid1, low) × (1 − k/1e4))`，k ∈ {0, 5, 10}。挂出后**不随盘口追价**（位置固定）。
- 梯子存活 `T_live = 180 s`（从挂出算）；到期撤掉未成交的层。已成交的层进入持仓。
- 回测里梯子成交 = 卖方主动成交价严格低于挂价（k=0 层若恰在 bid1 则按队列前量消耗）；实盘按真实成交即可。

### 2.3 持仓与出场

- `C` = 已成交各层的均价（每多成交一层重算）。
- **止盈**：1 张 post_only 卖单，数量 = 已成交总层数，价格 `ceil_tick(C × (1 + 5/1e4))`；若该价 ≤ bid1（post_only 会穿价）则挂在 ask1。每次 C 变化：撤旧挂新。
- **止损**：`mid ≤ C × (1 − 40/1e4)` ⇒ 撤止盈单，以对手 touch 限价 IOC（容差 2 tick）全平；未全成按市价补。
- **到时**：第一层成交后 1800 s 仍有持仓 ⇒ 撤止盈单，同上 taker 全平。
- 出场后：若为止损或到时 ⇒ 进入 COOLDOWN 60 min（两个方向都不开新回合）；若为止盈 ⇒ 直接 IDLE。
- 实盘不做日终强平（回测的日界是数据边界，不是策略）。

### 2.4 频控与延迟

- 每回合最多 3 挂 + 3 撤 + 止盈若干次撤挂；单合约 ≤ 5 次/s（与 Run A 同），超限延后。
- 回测假设挂撤生效 4 ms；Lo-La 实测 2.9 ms ack，满足。

### 2.5 急涨接空：逐项镜像（实现时两向共用一套代码，价格取负即可）

| 环节 | 急跌接多（dir=+1） | 急涨接空（dir=−1） |
|---|---|---|
| 触发 | 10 s 内 mid 较最高点跌 ≥ 10 bp；10 s **卖方**主动名义额 ≥ 5× 1 h 中位 | 10 s 内 mid 较最低点涨 ≥ 10 bp；10 s **买方**主动名义额 ≥ 5× 1 h 中位 |
| 确认 | 跟踪触发后最低点 low，mid ≥ low×(1+2bp) | 跟踪触发后最高点 high，mid ≤ high×(1−2bp) |
| 梯子 | 买单 @ floor_tick(min(bid1, low)×(1−k/1e4))，k∈{0,5,10} | 卖单 @ ceil_tick(max(ask1, high)×(1+k/1e4)) |
| 止盈 | 卖单 @ ceil_tick(C×(1+5bp))，≤ bid1 则挂 ask1 | 买单 @ floor_tick(C×(1−5bp))，≥ ask1 则挂 bid1 |
| 止损 / 到时 | mid ≤ C×(1−40bp) / 1800 s → 对手 touch IOC 卖 | mid ≥ C×(1+40bp) / 1800 s → 对手 touch IOC 买 |
| 重新武装 | 跌幅回到 > −5 bp | 涨幅回到 < +5 bp |

熔断对两向共用；同一时刻只持一向。

**方向表现差异（回测 35 天，lot 0.01）**：接多 456 回合 +127.2 USDT、胜率 93%、止损 25；接空 426 回合 +11.1、胜率 91%、止损 30；接空按周为 −36.7 / +20.5 / +21.3 / +32.8 / −8.6 / −18.3，不稳。只做多的变体（P3b）在 3 个窗口里 2 胜 1 负，未一刀切。**实现要求**：方向做成配置项（`enable_long` / `enable_short`，默认都开），journal 每行带 `dir`，Run B 按方向分别对表；若实盘接空每回合净 < 0，关掉 `enable_short` 不需要改代码。

## 3. 风控与 HALT（在策略之外）

- HALT：行情 stale > 3 s、429 连续 3 次、post_only 连续被拒 ≥ 5、保证金率低于阈值 ⇒ 撤所有挂单；持仓只允许出场路径。
- 日内熔断（安全阀，回测未用）：当日净 ≤ −3 × 回测日均（lot 0.001 时约 −1.5 USDT；lot 0.01 时约 −15）⇒ 当日停止新回合，持仓照常出场。
- 资金费结算前 60 s 不开新回合（与 v1 同）。

## 5. 标定方案（Run B，参照 P3 round 的流程）

- BTC 单合约，lot 0.001，一套配置不动，跑满 **≥ 7 个 UTC 日**（覆盖 ≥ 1 个周末）。
- 与回测对表（analysis round 在 qflow-research 新开）：
  1. 触发 episode / 天（回测约 35）与确认率；
  2. 梯子成交率：有 ≥ 1 层成交的 episode 占比（回测 82%）、各层成交占比、`queue_ahead` 分桶成交率；
  3. 止盈单成交占比与**被吃速度**（部分成交 → 全部成交的用时分布，这是未来分批止盈设计唯一能用的数据）；
  4. 每回合净 bp（回测样本外 +3.2）、按层数拆、止损次数 / 天（回测 ≈ 1.5）；
  5. 出场 taker 滑点（回测按 0）；
  6. 实盘与回测同日逐回合对齐（Run A 用过的方法）。
- 放行到 lot 0.01：每回合净 ≥ 回测 − 1 bp、梯子成交率 ≥ 回测 − 10 pp、7 天净 > 0。
