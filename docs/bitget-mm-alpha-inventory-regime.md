## 4. 行情状态（regime）定义

- 每分钟算 Bitget 中价 60 s 内高低幅度 `range60`（bp）与 Bitget 主动成交名义额；以 35 天分布定阈值：**极端 = range60 ≥ 35 天 p99**（敏感性 p98 / p99.5），并把极端分钟之后 5 分钟记为「极端余波」（反弹往往在这里）；其余为**平时**。另报 p90~p99 的「活跃」档作中间层。
- 拆账三种口径，全部报：
  1. **逐笔**：maker 成交按成交时刻所处状态，报 mo5 / mo30、每笔净（mo30 + 0.5）；
  2. **逐回合**：库存离开 0 到回到 0 为一回合，按「回合期间是否碰到极端分钟」分组，报回合净 bp / USDT、时长、最大库存、taker 次数；
  3. **逐分钟盯市**：库存 × 中价变动 + 当分钟已实现的费用 / 返佣，按分钟所处状态求和（三个状态的和 = 总净值，作对账）。
- 状态标签是事后的（用当天全分布阈值），只用来拆账，不进策略。若拆账显示某库存策略在极端里亏、平时里赚，下一步再做**因果检测的状态切换**（例如过去 60 s 幅度超阈值即降库存上限 / 停挂），那需要改引擎，本轮不做。

## 5. 判定口径

- 每格 IS（09-27~10-14）/ HO（10-15~10-31）/ ALL：日净 USDT（含费）、净正日比例、最大单日亏损、最大回撤、每笔净、maker 成交 / 时、taker 次数 / 天。
- 极端 / 余波 / 活跃 / 平时四档各自的日均净、占时间比例、每单位时间净值。
- **容量**：极端分钟里每次 taker 平仓与 maker 平仓所需量相对当时 Bitget L1 对手量与成交量的比例；按 lot 0.1 BTC 与 1 BTC 估算「平仓单能否在反弹高点成交」（博主的教训）。
- 放行：存在轻惩罚格使 ALL 日净 > 重惩罚基线，且 IS / HO 同号、净正日 ≥ 70%，并且优势不全靠极端余波里的少数几天（剔除日净最高的 3 天后仍成立）。

2. **只有「不设库存上限」赚钱，而且赚的全是库存涨跌，不是做市。** 拆开看（7 天合计，D3 / D4）：库存随价格的盈亏 +1413 / +1047，其中极端加余波分钟 +1469 / +717；成交价差 −790 / −295，返佣 +393 / +167。也就是说，做市本身（价差 + 返佣）是亏的，利润来自暴跌里越跌越买、扛着最多 1317 手（D3）/ 657 手（D4）的多头等反弹。逐回合看，D3 有 4 个碰过极端的回合合计赚 1067，持仓中位 17 小时。
3. **这正是博主的形态，但它是方向性押注**：极端阈值从 p99 收紧到 p99.5，D3 不设上限那一格的极端档从 +40 变成 −19/天；这一周恰好是来回震荡、每次急跌都反弹的行情。
4. **容量**：不设上限那一格按 lot 0.1 BTC 折算，库存中位 15~20 BTC。平时分钟里「整个库存 / 当分钟打到我方的主动成交量」> 1 的占比 70%（D3），按 lot 1 BTC 是 97%。也就是库存一大就平不掉，和博主 1000 万美金账户的遭遇一致。

**先行判读**：在修后引擎上，「alpha 定价 + 轻库存惩罚」本身没有改善做市，四种行情里都更差；唯一的正收益来自无上限扛库存押反弹，属于方向策略，且这 7 天是对它最有利的震荡周。是否成立要看 35 天（含单边周）的结果。
