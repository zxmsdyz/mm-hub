# Bitget 冲击-回归做市（v0 设计，2026-11-08）

> 用户 2026-11-08 的判断：常规 touch 做市赚的是非知情流的滑点 / 返佣，这条赛道由顶级做市商把持；我们所有因子都是 BN 其他做市商报出 L1 之后的二手信息，拿二手信息去赚本该靠一手信息赚的钱大概率不可行。出路只有两条：① 找到预测价格的一手信息；② **只在特殊行情下吃对手单**。本文做第二条：Bitget 上突然出现 taker 大单、Bitget 的价格 / 挂单量变化**比 BN 大得多**（大概率是某个大户在 Bitget 开仓），此时作为 maker 给他提供流动性，博 Bitget 价格向 BN 回归。
>
> 前提沿用已决事项（[bitget-mm-strategy.md §8](bitget-mm-strategy.md)）：maker −0.5 bp、API taker 1.5 bp、UTA、只做 BTC / ETH / SOL。Run A 实盘（§12.3）已证明 touch 做市每笔净 −0.36 / −0.32 bp，本文是对它的**替代**而不是补丁。
>
> 本文是设计 + 回测方案，不含代码；回测在 qflow-research round 里做（§6），结果回填 §7。

---

## 0. 一句话

**不在 touch 排队，而是把 post_only 单挂在「BN 公允价 ± D bp」的位置等 Bitget 自己的大单扫过来；成交即意味着 Bitget 相对 BN 偏离了 D，随后挂 maker 平仓单等它回归，T 秒不回归或继续偏离到 D+SL 就 taker 认赔。** 收入 = 偏离回归幅度 + 返佣，成本 = 不回归的那部分 + 偶发 taker；它与 touch 做市的根本区别是：**成交只发生在「Bitget 比 BN 多动了 D」这个被条件化的时刻**，不需要和 BN 做市商比快。

## 1. 机制与经济账

### 1.1 为什么这类成交可能不毒

| | touch 做市（Run A 实盘） | 冲击-回归 |
|---|---|---|
| 成交发生时刻 | 本档前量被其他做市商撤空、档位随即消失（79~84%），BN 与 Bitget 同毫秒同向推进 | Bitget 被一笔 / 一串主动单扫穿 D bp，而 BN 同一时刻没动或动得少 |
| 对手是谁 | 跨所套利 taker、与 BN 同步的知情流 | Bitget 本地的流动性需求者（大户开 / 平仓、强平、程序化 TWAP 冲击） |
| 成交价相对公允 | ≈ 0（恒 1 tick 价差） | **D bp 的让步在成交瞬间已经拿到** |
| 之后价格怎么走 | 继续同向（mo30 −0.86） | 两种收敛路径：Bitget 回归 BN（我们赢）或 BN 跟上 Bitget（Bitget 领先 = 知情，我们输） |
| 量 | 排队成交率 17~23%，lot 受队列限制 | 事件稀少（每天几十次量级待测），但**单次可挂大 lot**：扫 D bp 的单子本身几十 BTC，我们 0.1~1 BTC 不是边际 |
| 对延迟的依赖 | BN 事件撤单需 ≤ 3 ms，实测仍来不及 | 挂单离 BN 公允 D bp，BN 要在撤单延迟 4 ms 内走完 D bp 才会误成交；D ≥ 1 bp 时几乎不可能 |

**关键经验证据（Run A 分析，§12.3）**：实盘成交里「BN 后动 / 无 BN 事件」的子集占 57~73%，其中档位存续（没被撤空）的那 16~20% mo30 −0.19 ~ −0.36，每笔净为正。说明 Bitget 上存在**不与 BN 同步**的成交机会，只是 touch 形态拿不到好价。另一条旁证：gate↔bitget / HTX↔bitget 价差回归线（qflow-research candidates 2026-10-20/26）显示 Bitget 对另一所 ≥ 2 bp 的偏离每天 30~40 次、两腿对冲回归 wr 2.5~3.3 bp，胜率 99%——Bitget 确实会单独偏离并回归，**只是那条线用了两腿对冲 + taker**。本文是它的「单腿 maker 版」：不对冲、靠 D 的让步与返佣替代对冲成本，承担「BN 跟上来」的方向风险。

### 1.2 每回合的账

```
每回合净 bp = R·D            （回归拿回的部分，R = 回归比例 ∈ [0,1]）
            + 0.5             （进场返佣）
            + 0.5  或 −1.5     （maker 平仓 vs taker 平仓）
            − 半价差 × 2 ≈ 0   （1 tick 品种忽略）
            − 止损摊销         （偏离继续扩大到 D+SL 的概率 × (SL + 1.5)）
```

| D（bp） | R=0.7、maker 出 | R=0.7、taker 出 | R=0.3、taker 出 |
|---:|---:|---:|---:|
| 1.0 | +1.7 | −0.3 | −0.7 |
| 2.0 | +2.4 | +0.4 | −0.4 |
| 3.0 | +3.1 | +1.1 | −0.1 |

读法：① **maker 出场是否可行决定一半收益**，而 maker 出场能否成交取决于回归后 Bitget 盘口是否「穿回来」到我们的平仓价——这是回测要专门测的（§6.3）；② D 越大每回合越厚但事件越少；③ R 是核心未知数——如果收敛主要靠 BN 跟上（R≈0），整条线不成立。

### 1.3 规模账

touch 做市 lot 0.001 BTC 一天 600 笔 × 0.14 bp（回测乐观值）≈ 0.6 USDT/天。本线若每天 20 次事件 × 2 bp × lot 0.1 BTC（7,600 USDT）≈ 3 USDT/天，lot 0.5 BTC ≈ 15 USDT/天。**lot 能放大是因为对手单本身大**；上限由「我们的量相对扫单量的占比」与止损预算（lot × (D+SL) bp）定，不由队列定。

## 2. 事件定义（因子）

全部用交易所时间戳对齐（Run A 教训：collector 到达钟把 Bitget 拉晚 6~8 ms）。BN 公允价 `fv_bn` = BN 永续 bookTicker 微价（`mp_bn`，R2-e 证明基差均值项是噪声，不加）。

| 符号 | 定义 | 用途 |
|---|---|---|
| `dev` | `(mid_bg − mp_bn) / mp_bn × 1e4` bp，Bitget 相对 BN 的即时偏离 | **主触发 / 挂单位置**：卖单挂 `mp_bn × (1 + D/1e4)`，买单挂 `mp_bn × (1 − D/1e4)`（取整到 tick，post_only） |
| `Δdev(W)` | `dev(t) − dev(t−W)`，W ∈ {100, 300, 1000} ms | 「Bitget 比 BN 多动了多少」，用户所说「价格变化比 BN 大」的量化；S2 反应式触发用 |
| `move_bn(W)` | `|mp_bn(t) − mp_bn(t−W)|` bp | BN 自己是否也在动；`move_bn(W) ≤ m` 作为「BN 没动」门（m = 0.5 bp 起） |
| `V_tk(W)` | Bitget 最近 W 内带符号 taker 成交量（BTC） | 用户所说「taker 大单」；`V_tk(500 ms)` 与其 24 h 滚动中位数之比 = **量比** `vr` |
| `n_tk(W)` | 同窗成交笔数 | 区分「一笔大单」与「一串小单」 |
| `depl(W)` | Bitget 自侧前 N 档（books50）名义量相对 W 前的缩水比 | 用户所说「挂单量变量比」；只有 depth_l2 的日子（10-25~31、11-04、11-07）可算，作为 S2 的备选触发 |
| `vr_bn(W)` | BN 同窗 taker 量比 | 若 BN 同时也在放量则不是 Bitget 本地事件，门：`vr_bn ≤ k_bn` |

事件 = `dev` 越过 ±D（S1 的成交本身就是事件），或 `Δdev(W) ≥ D 且 move_bn(W) ≤ m 且 vr ≥ k`（S2）。阈值网格见 §6。

### 2.1 成交流的三个数（用户 2026-11-08 另一会话的买卖压力分解，移植到秒级窗口）

带符号净量 `V_tk` 把「对攻」与「清淡」算成一样、把「大量里的小倾斜」算得比「一边倒」还大，且与总量重复计数。改用三个数 + 一个规模数，窗口 W ∈ {300 ms, 1 s}，参考分布 = 同长度窗口在过去 1 h 的滚动分布（亚秒窗口大多为空，参考分布只取非空窗口，ε = 参考窗口总量中位数的 1%）：

| 指标 | 算法 | 回答 |
|---|---|---|
| 买量 σ `zB` | `ln(B+ε)` 相对参考分布的 z | 买方是否特别猛 |
| 卖量 σ `zS` | `ln(S+ε)` 相对参考分布的 z | 卖方是否特别猛 |
| 倾斜 σ `zK` | `ln((B+ε)/(S+ε))` 的 z | 方向倾斜是否异常；**只在总量 ≥ 参考中位数时才算数** |
| 平均单笔 σ `zA` | `ln((B+S)/n_tk)` 的 z | 大单主导还是散单主导——本线论点是「大户开仓」，这一维必须分桶 |

读法映射到本线：
- **买压冲击**：`zB` 过线且 `zK > 0`（卖压对称）→ 这是 S2 的触发，也是 S1 成交时刻的事后标签；
- **对攻 / 吸收**：`zB`、`zS` 都过线、`zK` 不显著、价格没动 → **不是进场场景**，S2 排除；S1 若在此状态成交要单独看 R；
- 事件表（§6）按 `zA` 高 / 低、`zK` 显著 / 不显著分桶报 R(30 s)：预期大单主导（`zA` 高）的冲击回归更干净，散单 TWAP 式（`zA` 低、持续放量）更像知情或持续性流，回归差。

`vr`（量比）保留作粗门，分析表以这四个 σ 为准。

## 3. 策略形态（三个变体，回测全部跑）

### S1 · 公允价锚定深挂（主形态，我的选择）

```
每帧（BN 或 Bitget L1 更新）：
  target_ask = round_up(mp_bn × (1 + D/1e4));  target_bid = round_down(mp_bn × (1 − D/1e4))
  若在簿卖单价 与 target_ask 差 ≥ step（如 0.2 bp）→ 撤 + 重挂（延迟 L_c + L_p）
  若 Bitget ask1 ≥ target_ask（盘口已经先到了）→ 不挂卖（避免挂进已经被扫的位置后面）
  两侧同时挂，各 1 lot；库存 ≠ 0 时只挂减库存侧（同 touch 形态）
成交（卖出 @ P_in，即 dev ≥ D）→ 进入 EXIT：
  E1 maker 平仓：买单挂 max(bid1_bg, mp_bn × (1 − x/1e4))，x ∈ {0, 0.5, 1}，随 mp_bn 每帧重挂
  E2 时间止损 T_max ∈ {10, 30, 60, 120} s 未平 → 对手 touch 限价 IOC（1.5 bp）
  E3 价差止损：dev 继续扩大到 D + SL（SL ∈ {3, 5, 10} bp）→ 立即 IOC
  E4 变体：回归目标改为 dev ≤ D·(1−R*)（部分回归即平），R* ∈ {0.5, 1}
```

优点：永远在场，不需要「先检测再追」，拿到队列优先；对延迟不敏感。缺点：挂单离盘口远，大部分时间空等；Bitget 挂单数、改单频率限额（每合约 200 单、改单 10 次/s）需要 step 不要太细。

### S2 · 反应式 touch 追挂

```
触发：Δdev(W) ≥ D 且 move_bn(W) ≤ m 且 vr ≥ k（W=300 ms 起）
动作：在冲击方向的对手侧 touch 挂 post_only（买方冲击 → 挂 ask1 卖）
      只挂 T_live（如 2 s），期间 dev 回落到 D/2 以下即撤（冲击结束，不追了）
成交条件：冲击继续、扫到我们这一档
出场：同 S1 E1~E4
```

与 S1 的差别：S2 只在冲击确认后挂，成交价是冲击后的 touch（通常比 fv+D 更深），但要和冲击赛跑（Bitget 自家 L1 → 本地 → 挂单 ≈ 0.45 + 2.9 ms，§12.4.1），且成交被「冲击继续」条件化——这正是 touch 做市里最毒的那类成交，差别只在 dev 门。**S2 对 S1 是对照组**：若 S2 明显差于 S1，说明「被条件化为继续」的毒性压过了 dev 门的保护。

### S3 · 梯子（S1 的多层版）

两侧各挂 D1 < D2 < D3 三层（如 1 / 2 / 3 bp），各 1 lot，库存上限 3 lot，平仓按 FIFO 各自挂 maker。用于看「深层是否更干净」以及大冲击时摊薄成本。v1 不上，只回测。

### 共用规则

- 库存上限 `Q_max`（S1/S2 = 1 lot，S3 = 3 lot）；库存 ≠ 0 时同侧不再加。
- HALT：BN 或 Bitget 行情 stale > 1 s、429、资金费结算前 60 s（偏离常在结算前后放大且不回归）。
- **不对冲**（对冲就回到 gate/HTX 价差线，那条线的成本结构已知）。
- lot：标定期 BTC 0.001 / ETH 0.01；放量阶段按「≤ 扫单量中位数的 10%」定。

### 6.2 引擎规则（自建、非 canonical；与 P1 引擎的差别明写）

1. **时间轴**：两所都用交易所时间戳；BN bookTicker `T`、Bitget `exchange_ts`。两所钟偏移未知，敏感性 ±3 ms（Run A Q7 方法）。
2. **挂撤延迟**：本地看到 → 单进簿 L_p = 4 ms（Lo-La 实测下单 ack 2.9 + 行情 0.45 + 决策），撤单 L_c = 4 ms；敏感性 {2, 4, 10, 50} ms。
3. **成交规则（保守）**：我们的卖单 @P 成交 ⇔ Bitget 公共 trade 流出现 **买方主动、价格 > P**（严格穿过），或价格 = P 且该价位累计成交量 ≥ 该价位我们挂单时的可见量（depth_l2 日子精确、L1 日子只有当 P 在 L1 时可算，否则按「严格穿过」）。不给撤单信用（α = 0，Run A 结论）。
4. **成交量**：按 lot 全成交；另报「事件时 trade burst 总量」用于 H5。
5. **出场**：E1 maker 平仓按同一成交规则；E2/E3 taker 按对手 touch 成交、费 1.5 bp、滑点 0（lot 小）。
6. **重挂频控**：step 0.2 bp；单合约挂 + 撤 ≤ 5 次/s，超出则延后到下一帧。
7. **指标**：每回合净 bp（含费）、maker 出场占比、持仓时长分位、事件 / 天、R(5/30 s)、按 UTC 日净 USDT（lot 0.001 与 lot 0.1 两档）、IS/HO、正日比例、最大单回合亏损、p10；每笔 markout mo5/mo30 与 touch 做市对照。
8. **安慰剂**：随机时刻、同样 lot、同样出场规则的「假事件」回合；S1 的位置从 `mp_bn ± D` 换成 `mid_bg ± D`（不参考 BN）作对照——若两者无差，说明赚的只是 Bitget 自身的波动回归，不是跨所偏离。

**机制（为什么 S1 亏）**：挂在「BN 微价 ± D」的深挂单本身就是一个**跟 BN 走的报价**；BN 每动 0.2 bp 就要撤 + 重挂一次，频控 5~10 次/s 下单子经常落后目标，成交恰好发生在单子已经陈旧的时刻（`stale_in` = −0.3 ~ −3 bp），实际拿到的让步只有名义 D 的 20~50%（BTC D=2 名义 2 bp，实际 0.97）。这和 touch 做市被狙击是同一个机制，只是换到了深处。不限频控时让步回到 1~2 bp，结果转正，说明问题出在「深挂需要紧跟 BN」这个形态上，而不完全是回归不存在。

**副产品（可能是一手信息）**：Bitget 自己成交流里「冲击方向主动量 σ」对 touch 成交的后续毒性有单调区分度，见 H6 一行。它是 Bitget 本地、在成交前 300 ms 就可见的量。用法不是 fade，而是 touch 做市的**撤单 / 不挂门**（冲击方向 σ ≥ 2 时撤掉对手侧报价），或者作为方向信息。单日、样本小（BTC zDir > 3 只有 27 笔），需要 35 天复核，暂列为待验证项。

**门 0**：H6 不成立；R(30 s) 均值 ≥ 0.5 名义上满足，但 H3 反向、S1 在可行频控下全负。本应停在这里；考虑到只有 8.6 h 样本且不限频控的格为正，继续跑 Stage 1（35 天 BTC），重点看两件事：频控 20 次/s 与去基差锚两个变体在 35 天上是否 IS/HO 同号为正；R 与 H3 的反向关系在 35 天上是否稳定。

### 7.3 判定（2026-11-08）

**DROP：S1 / S2 / S3 三种形态的冲击-回归做市在 Bitget BTC 上不成立。** 原因不是参数或延迟，是假设本身：Bitget 上会扫穿到我们挂单价位的本地冲击是知情流，BN 随后跟上，而不是散户 / 大户把价格砸偏后回弹。ETH 未做 35 天，但 Stage 0 单日上 H3 同样反向、可行频控下同样全负，不单独再跑。

**留下来的东西**：
- **Bitget 本地冲击方向的主动量 σ 是毒性信号**（Stage 0 H6：Run A touch 成交按成交前 300 ms 冲击方向 σ 分桶 mo30 单调变差；本轮 event_features：|zK| ≥ 2 一档最差）。它在 Bitget 本地、成交前可见，是 touch 做市「撤 / 不挂」门的候选，也是这条线里唯一像一手信息的东西。需要先在 35 天 touch 回测（引擎修复后）上验证增量，再谈用法。
- 方向上：若真想用「Bitget 冲击后 BN 跟进」这个现象，它是**跟随**而不是 fade；但 R4 已证明跟随吃单扣 taker 费后为负，这里不再展开。
